# Wonder_Pop | MASTER TASKS.md

> **Plan created 2026-10-12.** Status ALL `PLANNED / GATED`. This is planned product work, NOT evidence that the SDK is already Unity 6.6 compatible or any game has been built.

## Product thesis
- **Wonder Pop | ages 5–12, restoring color to picturebook worlds**.
- Worlds (proposed, owner can revise): Doodle Village; Rainbow Carnival; Teddy Toyland; Butterfly Garden; Melody Town; Dreamland.
- Piece skin candidates (require creative approval): paint drop, star, sunshine icon, fluffy cloud, clover, rainbow pencil.
- Thematic obstacles: scribbles, tangled ribbon, frozen colors, sticker box, paint spread. Progress events: restore fading scenes, bring back color and unlock charming world characters. Special VFX: magic brush, glitter burst, rainbow pencil, color splash.
- Style brief: bright soft premium 2D/2.5D, distinct silhouettes, kid-friendly animations. Design distinction: NO Creative Studio, character creator, room decorator or drawing mode; progress identical to four other games.
- Audience / safety: children 5–12; privacy first, no targeted advertising; parental gate for links/purchases if offered.

## Dependency and release gates
- **NO branded-game code/assets or Codex implementation until** BOTH `Sekiph82/MATCH3_ENGINE` ENG-M24 final release audit PASS and `Sekiph82/Match3-Level-Factory` LFX-M14 final audit PASS, unless owner explicitly revises gate.
- Keep Match3-SDK as shared Unity package via ENGINE. No second match algorithm, custom gravity or special-combination solver. All five games use identical level JSON/world/chapter/stars/tasks/economy/save/remote-update contracts.
- First 3 early-level intents are inspired by Daltonbr/Match3, whose repo does not currently establish permission for code/asset reuse. Independently create levels using our SDK-based runtime. Scene files are NOT imported.
- Chapter/story milestones use shared abstract `ProgressAction`; theme-specific scene/character animations belong only in this repo.
- Remote content from Factory: level/schema/compatible asset changes only; no remote executable C#; signed hash manifests, atomic staging, offline cache and rollback. Game ID isolation required.
- **MOBILE SHIP-BUILD EXCLUSION:** Commit tests and testing scripts to GitHub so CI can execute them, but shipping Android APK/AAB and iOS IPA must NOT contain NUnit/TestFramework/test assemblies, fixture levels or scenes, Editor-only/Factory tools, screenshots, audit logs or development evidence. Dedicated test asmdefs; release build scripts fail on `IncludeTestAssemblies`, enabled PlayMode test runner or forbidden player assets. Verify actual binary, Addressables, Resources/StreamingAssets and Player assembly manifest; keep runner output and media in Drive.
